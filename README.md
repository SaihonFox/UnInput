# UniversalInput

Модульная кроссплатформенная библиотека устройств ввода для .NET 10: единый API для обнаружения устройств, чтения событий, эмуляции и прямого доступа. Проектный документ (архитектура, решения, ограничения платформ) — Technical Design Document.

## Состояние

Готовы контракты, ядро, интеграция с Generic Host, mock backend, backend последовательных портов, тесты и пример. Клавиатуры, мыши, геймпады и HID библиотека пока не читает; платформы Windows, Linux, macOS, Android и iOS не заявлены как поддерживаемые.

| Проект | Что внутри |
|---|---|
| `UniversalInput.Abstractions` | Модели устройств, `InputEvent`, контракты backend и хаба, ошибки. Ни от чего не зависит |
| `UniversalInput.Core` | Реестр устройств, диспетчер событий, подписки, жизненный цикл backend, `InputHub` |
| `UniversalInput.Hosting` | `AddUniversalInput`, фоновая служба, настройки |
| `UniversalInput.Testing` | `MockInputBackend`, вспомогательные средства для тестов |
| `UniversalInput.Backends.Serial` | Backend COM-портов (System.IO.Ports): обнаружение опросом, сырые байты через прямой доступ |
| `UniversalInput.Backends.GlobalHook` | Backend системного ввода через глобальный хук ([SharpHook](https://github.com/TolikPylypchuk/SharpHook)): клавиатура и мышь всей системы, только наблюдение |
| `tests/*` | Тесты xUnit v3 (включая проверку правил зависимостей по файлам проектов) |
| `samples/UniversalInput.Samples.ConsoleApp` | Консольный пример на mock backend |

Правила зависимостей: Abstractions — ни на что; Core — только на Abstractions; backend — только на Abstractions, никогда на Core. Нарушение ломает тест `ProjectReferenceTests`.

## Подключение

```csharp
services.AddUniversalInput(input => input
	.AddSerial(options => options.PollInterval = TimeSpan.FromSeconds(1))
	.AddGlobalHook());
```

Пакет backend зависит только от `UniversalInput.Abstractions`: метод расширения (`AddSerial`) вешается на `IInputBackendBuilder`, который реализует построитель из Hosting.

## Сборка и проверка

```
dotnet build UniversalInput.slnx
dotnet test UniversalInput.slnx
dotnet run --project samples/UniversalInput.Samples.ConsoleApp
```

Проекты xUnit v3 — исполняемые, поэтому каждый тестовый проект можно запустить и напрямую: `dotnet run --project tests/UniversalInput.Core.Tests`.

## Что устроено иначе, чем в первой версии проектного документа

- При переполнении подписки относительное движение мыши и колесо **суммируются**, а не заменяются последним значением (иначе смещение терялось бы); абсолютные значения — позиция, оси, касания, датчики — заменяются последним.
- `StreamGap` для потерь на уровне очереди backend ставится после уже доставленных событий; точное место пропуска относительно соседних событий приблизительное.

## Арбитраж между backend

Когда одно физическое устройство видят несколько backend (например, Sdl и Hid для геймпада), Core показывает **одно** логическое устройство с одним `DeviceId`:

- Дескрипторы объединяются при совпадении `VendorId`, `ProductId`, серийного номера и шины. **Без серийного номера объединения нет**: два одинаковых устройства без серийников неразличимы, лучше показать два устройства, чем склеить разные.
- Для каждой роли (`Observe`, `Emulate`, `DirectAccess`, `Output`) выбирается один владелец среди backend, которые её объявили. Порядок — `InputHubOptions.KindPriority` (по умолчанию геймпады и джойстики: Sdl, Hid; клавиатуры и мыши: Native, Hid), для сырых reports `RawAccessPriority` (Hid, Native), затем общий `BackendPriority`, затем порядок регистрации. Выбор виден в `InputDevice.Providers` и `InputDevice.RoleOwners`.
- События доставляются только от владельца `Observe`; события остальных поставщиков отбрасываются (метрика `not_role_owner`), иначе подписчик получал бы каждое нажатие дважды.
- Если владелец роли пропал, а другой поставщик остался, устройство не исчезает, роли переходят к оставшемуся, `DeviceDisconnected` не публикуется. Канал прямого доступа, открытый через ушедший backend, закрывается.
- Агрегатные события (глобальный хук) клавиатуры и мыши считаются дублями, пока подключено хотя бы одно устройство этой категории (не агрегат) с работающим `Observe`. Подписка без явного выбора (`Origins`, `Devices`, `DeviceKinds`) их не получает; чтобы получать, нужно указать `Origins = [DeviceOrigin.Aggregate]`. Если отдельных устройств нет, агрегатные события проходят как обычно. Агрегатное устройство у backend одно, поэтому приоритета для него нет.

## Предел частоты непрерывных событий

`SubscriptionOptions.MaxContinuousRate` (событий в секунду) ограничивает движение мыши, колесо, оси, касания и датчики. Первое событие проходит сразу, следующие склеиваются (относительное движение и колесо суммируются, абсолютные значения заменяются последним) и уходят одним событием по таймеру. Дискретные события не ограничиваются и перед собой выпускают накопленное движение того же устройства, поэтому порядок сохраняется. При завершении подписки накопленное не теряется.

Отличие от первой версии документа: предел действует на каждый поток отдельно (устройство + вид события + ось, касание или датчик), а не на устройство целиком: события разных осей нельзя склеить в одно.

## Backend GlobalHook

Один агрегатный device `globalhook:system` (вид `SystemWide`, источник `Aggregate`) на весь системный ввод: хук не сообщает, какая физическая клавиатура или мышь создала событие. Поэтому события несут флаг `Aggregate`, и Core прячет их как дубли, пока ту же категорию отдельно наблюдает другой backend.

- Поддержано только `Observe`. Эмуляция и перехват в SharpHook есть (подавление событий — только Windows и macOS), но здесь не подключены и честно объявлены неподдерживаемыми.
- Клавиши передаются кодом страницы клавиатуры USB HID. Клавиши без такого кода (мультимедиа, браузерные, часть японских и IME) не доставляются; список зашит в `KeyMap.Unmapped`, тест требует, чтобы каждый код SharpHook был либо переведён, либо в этом списке.
- Мышь: только абсолютные координаты. Колесо: `DeltaY` > 0 — вверх, `DeltaX` > 0 — вправо; единицы берутся из ОС как есть и между ОС могут отличаться.
- События, созданные программами (в том числе самим приложением), получают флаг `Simulated`; автоповтор клавиши — `Repeat`.
- macOS: нужно разрешение «Универсальный доступ»; без него запуск завершается `PermissionDenied` с инструкцией. Linux: нужен X11 или Wayland; на Wayland нет абсолютных координат и повышены требования к правам (udev). Ошибки запуска не скрываются, а попадают в статус backend.
- Поддерживаемые SharpHook платформы: Windows (x64, x86, arm64), macOS (x64, arm64), Linux (x64, arm64, arm32). Мобильные платформы и браузер отклоняются проверкой.
- **Не проверено ни на одной реальной ОС**: тесты работают с подменённым источником хука; логику SharpHook я проверить не мог.
